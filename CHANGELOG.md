# Changelog

All notable changes to this project. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning: SemVer per component — server crate and web package are versioned independently. Entries are tagged `(server)`, `(web)`, `(infra)`, `(docs)`.

## 2026-08-07 — the web application: real API client, app shell, and the auth/account/token/org screens

The frontend stops being a skeleton. `packages/api` grows into the client the app actually needs (bearer injection, proactive and reactive refresh, a denial latch, typed modules per area), module-level Solid stores replace the placeholder island, and the screens whose endpoints are already committed are built end to end. Everything the app API has not shipped yet is a visibly marked placeholder, not fake data.

**One refresh, or the reuse detector eats the session.** A page that loads six things in parallel used to be a design problem waiting to happen: six 401s, six refreshes, five of them presenting a rotated-out token, and [S-08](docs/security.md#2-sessions--web-plane)'s reuse detection killing the family as a direct consequence of loading a page. Refresh is therefore single-flight — proactively (the access token's `exp` is decoded and refreshed inside a 60 s skew window, so the cost lands before the user's click rather than during it) and reactively (concurrent 401s share one promise, and each request is cloned *before* its body is consumed so the retry is intact). A refusal closes a **denial latch**, so a dead session costs one request instead of one per click.

**A tunnel is not a logout.** `NetworkError` and `ApiError` were already distinct types; the interceptor is where that distinction earns its keep. A transport failure during refresh propagates untouched: the latch stays open, the stored pair stays, and `onAuthLost` is never called. Only a *refusal* clears storage and signs the user out — asserted from both the proactive and reactive paths, including recovery once connectivity returns.

**The step-up gate is split between the layer that sees it and the layer that can act on it.** An interceptor spots the distinct `step_up_required` 403 ([S-06.a](docs/security.md#1-authentication)) and opens the prompt, because it sees every response; the *caller* owns the retry, because only it knows whether the action is still wanted after the user has typed a code. One shared prompt, many waiters, no stacked dialogs — `withStepUp(() => …)` at each gated call site.

**A QR code without a dependency.** 2FA enrollment shows a real scannable code from a ~350-line byte-mode encoder (level M, versions 1–9, Reed–Solomon over GF(256), all eight masks scored) rather than pulling a library into a security screen. It is validated by *decoding its own output* with an independently written reader, plus the published format/version-information tables — a transposed coordinate or a mis-sized block split fails the round trip. Payloads too long to encode fall back to manual secret entry.

## 2026-08-07 — realtime layer, and an adversarial review of the whole app API

The event bus of [decision 22](docs/decisions.md#22--domain-event-bus-webhooks-and-integrations-on-top) is real, and two consumers hang off it: the SSE stream of [decision 20](docs/decisions.md#20--realtime-sse-event-stream--notification-center) and the notification center. Migration **0009** adds `notifications` and `notification_prefs` to both backends. The second half of the slice is a fresh-eyes pass over every route the app API exposes, phases 1–2 included.

**One bus, and the fan-out order is the design.** Domain services emit into `EventBus` (new crate [`pub-events`](server/crates/events)); it broadcasts in-process, republishes to the KV broker topic so any instance can serve any client's stream, and then runs its consumers. Consumers run **only on the emitting instance** — a peer feeds an inbound event to its stream and to nothing else, or N replicas would file N notification rows for one event. Consumer output (one `UserNotified` per recipient) re-enters the stream but never the consumers, so there is no cycle to bound. The audit log is deliberately *not* a consumer: it is durable truth under S-22, while the bus is a hint channel whose consumers may fail silently.

**The stream's audience is a property of the event.** `DomainEvent::audience()` answers `Org` | `Instance` | `User`, and the SSE filter consults nothing else — no package flags, no per-variant special case — through the same `authorize()` chokepoint the REST paths use. Adding an event variant without deciding its audience does not compile. Replay applies the identical filter, so reconnecting with a `Last-Event-ID` cannot widen what a principal sees.

**"Terminate within one access TTL" is enforced at startup.** The heartbeat is where a stream re-checks the revoked-`sid` blocklist and re-reads the account row, so the config validator refuses `realtime.heartbeat_secs >= auth.access_ttl_minutes`. A KV failure during the re-check closes the stream, and the stream ends at the token's own `exp` regardless.

### Added

- (server) **`GET /api/v1/events`** — the SSE stream (S-32). Access-JWT authenticated through the same extractor as every REST route (fetch-streaming, because `EventSource` cannot set `Authorization`), heartbeats that re-check revocation and the instance-admin flag, an RAII per-user connection cap answering `429 + Retry-After`, authorization filtering, and best-effort `Last-Event-ID` replay from a bounded per-instance ring. Frames carry `id:`, `event:` (the dot-namespaced type), and a `StreamEvent` document that is in the OpenAPI spec like every other payload.

Three categories (`package`, `org`, `security`) with the event→category map on the event itself; `org` and `security` are the high-importance tier and reach a mailbox through the existing `Mailer` unless the user turns them off. Fan-out is at write time, one row per recipient, bounded by `realtime.max_notification_recipients`.
- (server) **`pub-events`** — `EventBus` (broadcast + broker bridge + replay ring + connection budget) and `NotificationCenter`, behind the `EventConsumer` seam an outbound-webhook worker will implement unchanged (v1.1).
- (server) **`NotificationRepo`** on both backends plus migration 0009, contract-tested on SQLite and Postgres. Every statement carries `user_id`: a foreign notification id handed to mark-read changes nothing and reports nothing, because reporting it would be an existence oracle.
- (server) **`[realtime]` config** — `heartbeat_secs`, `max_connections_per_user`, `replay_buffer`, `max_notification_recipients`, `notification_email`, all validated at startup and printed in the effective-config summary.
- (server) **`surface.rs`** — the route inventory as a test. The generated OpenAPI document must match a hand-maintained list of every `(method, path)` **exactly**, every authenticated route must declare the bearer scheme, every mutation must refuse an anonymous caller *and* demand the S-12 header, every paginated route must answer a tampered cursor with one clean 400, and no schema may carry a credential-shaped field outside a named allow-list.

The Postgres contract leg ran green against a throwaway `postgres:17-alpine`.

### Fixed

- (server) **The package page walked every version of a package.** `GET /api/v1/packages/{name}` loaded the complete version list — one query per hundred versions, on an anonymous-reachable route — to compute three fields. It now derives `latest` from a bounded newest-first scan that terminates at the first live stable release (one query for essentially every package) and takes `versions_count` from a new `PackageRepo::count_versions` aggregate.
- (server) **Two N+1 reads in listings.** A package's version history resolved a publisher account per row, and the org members table read an account per member. Both go through one batched `UserRepo::get_many` now; the members lookup is chunked, so a large org is a few round trips rather than a refused query.
- (server) **Creating an org wrote no audit row.** `POST /api/v1/orgs` went straight to the repository, so the only trace of a new organization — a namespace, an Owner, and a virtual registry base — was the row itself. It goes through `OrgService::create_org` and writes `org.created` (S-22).
- (server) **The audit viewer's actor filter silently answered "nothing".** It parsed any id as a *user* id while documenting that it matched tokens too, so filtering by a CLI token id returned an empty page for an actor that had been publishing all week. The filter is `(actor, actor_kind)` now, `user` by default, and an unknown kind is a 400.
- (server) **The invitation list was unbounded.** Invitations accumulate without anybody deleting them — the S-24 budget alone allows 20 a day forever — so the response grew without limit. It is capped at 200 newest-first rows with a truthful `has_more`; a cursor lands when that screen gains filters.

### Changed

- (server) **The `NoopEventSink` wiring is gone.** `RegistryService`, `UpstreamService`, `OrgService`, and `AdminService` all emit into the real bus, so publishes, retractions, option changes, hard deletes, transfers, membership changes, org lifecycle, settings changes, and the S-17/S-19 proxy alarms all reach the stream and the notification center.
- (server) **`DomainEvent` gained `audience()`, `summary()`, and a `UserNotified` variant**, and `notification_category()` now returns a typed `NotificationCategory`. The ULID codec moved into `core::id` so audit ids and event ids cannot drift into two orderings.
- (docs) Implementation addenda on [decision 20](docs/decisions.md#20--realtime-sse-event-stream--notification-center) (audience on the event, the per-instance ring, emitting-instance-only consumers, write-time fan-out, the three categories, and the org-deletion gap) and [decision 22](docs/decisions.md#22--domain-event-bus-webhooks-and-integrations-on-top) (why audit is not a consumer, infallible emission, the webhook seam); new [S-32.a](docs/security.md#7-platform).

### Notes

- **Deleting an organization notifies nobody.** `OrgDeleted` is org-scoped and the deletion has already removed every membership by the time it fires, so the audience resolves empty. The affected members do get their sessions revoked, which is the signal they act on; closing it properly needs a recipient list on the event and lands with webhooks.
- **Org member listings are still single-page.** Truncating them is worse than not paginating them (an Owner could vanish from the table), so they stay unbounded in row count while the account lookups behind them are batched and chunked. Cursor pagination lands with per-package grants, which is when an org is expected to be large.
- **The stream's org roles come from the access token**, like every other read path. They cannot be stale-high — any role change revokes the session and the next heartbeat kills the stream — only stale-low, which fails closed.

## 2026-08-07 — management and administration surface

Everything a human changes: the org danger zone, package moderation, and the instance-admin panel. Migration **0008** adds `users.is_instance_admin`, `orgs.description`, and `orgs.archived_at` to both backends, plus the indexes the new listings and gates read.

Three rules shape the slice, and each of them lives one layer below the routes so a handler cannot forget it.

**S-09 is a service, not a checklist.** Every membership mutation is classified as a grant, a redefinition, or a withdrawal ([`AuthorityChange`](server/crates/admin/src/orgs.rs)), and the last two revoke every session of the affected user before the call returns. `OrgRepo`'s membership mutators have exactly one caller each — `OrgService` — so "no route can forget" is structural. A pure **grant** deliberately does not revoke: a token issued before it carries no claim for the org and fails closed, and logging somebody out of every device the instant they accept an invitation costs UX for no security. The rule and its table are in [S-09.a](docs/security.md#2-sessions--web-plane).

**Deleting an org that owns packages archives it.** Name claims and version rows are exactly what [decision 06](docs/decisions.md#06--retract--admin-only-hard-delete-with-tombstone) keeps forever, and both hang off the org row — so erasing it would un-burn a package name. `DELETE /api/v1/orgs/{slug}` refuses with 409 while packages exist; `force: true` stamps `archived_at`, strips members, invitations, and tokens, and flips every package private + unlisted + discontinued *through the registry service* so the search index follows. An org with nothing durable behind it is erased outright.

**Runtime settings actually take effect.** Registration mode, the S-31 domain allowlist, the S-24 rate limits, branding, and the instance upstream switch moved out of boot config into the `settings` table, read per request from an `ArcSwap` cache whose defaults *are* the boot config. A write goes repository → local reload → broker publish, with a 45 s version poll as the reconciliation fallback for messages a reconnect drops.

The ≥1-Owner invariant surfaces as a clean `409 last_owner` from the transactional repository check. Invitations are budgeted at ≤20/day/org (S-24) and return their token once, so an instance with no SMTP configured can still onboard people.

### Notes

## 2026-08-07 — search backend and the public read model

[Decision 11](docs/decisions.md#11--search-behind-a-trait) in both dialects, and the seven `GET` routes the web UI is built on. Migration **0007** (numbered after `0006_jobs_and_supply_chain`, which already existed) adds `package_search`, `package_tags`, and `download_stats` to each backend, dialect-idiomatic: a Postgres `tsvector` generated column with a GIN index plus a `pg_trgm` index on the name; a SQLite FTS5 external-content table kept in step by sync triggers.

The rule the whole slice is built around: **visibility is enforced inside the search implementation, through the chokepoint that already exists.** Every read takes a `SearchView` — the orgs in which `authorize(actor, ReadPackages, …)` succeeds, computed by *calling* that function — and each backend emits `visibility = 'public' OR org_id ∈ view` before anything a query string can influence. That covers the surfaces the pub protocol never had: a facet bucket, an instance counter, and a reverse-dependency edge disclose a private name just as effectively as a status code, so they run the same predicate and are asserted to agree with the listing ([S-04.d](docs/security.md#1-authentication)).

### Added

- (server) **`PackageSearch` per backend** ([db-postgres](server/crates/db-postgres/src/repo/search.rs), [db-sqlite](server/crates/db-sqlite/src/repo/search.rs)) behind the existing core trait, over a denormalized `package_search` document per package that has a live version. `package_tags` carries the exact-match dimensions (`topic:`, `dependency:`) and, with them, the reverse dependency graph read from stored pubspecs. Postgres additionally does fuzzy name matching through `pg_trgm` (`blok` finds `flutter_bloc`), which a lexeme index structurally cannot; SQLite gets prefix matching. The backends may differ in recall, never in visibility.
- (server) **A hand-written query parser** ([core/src/search.rs](server/crates/core/src/search.rs)) over the tag vocabulary that applies to us: `format:` `org:` `topic:` `dependency:` `is:private|public|discontinued|unlisted|retracted-latest` `sort:`, quoted phrases, and a leading `-` to negate any filter. It **never fails** — unparseable tokens are collected into `unknown_filters` and echoed back, so a search box cannot produce an error page and a malformed filter is indistinguishable from one that matched nothing. Untrusted text never becomes engine syntax: every term is quoted (FTS5 `"…"`, tsquery `'…'`), so `OR`, `NEAR`, `&`, `!`, `<->` and `:` inside a term are matched literally.
- (server) **Seven read-model routes**, all `GET`, all anonymous-reachable, all in the OpenAPI document: `/api/v1/packages` (search, facets, cursor), `/packages/{name}`, `/packages/{name}/versions` (newest first), `/packages/{name}/versions/{version}`, `/packages/{name}/dependents`, `/home` (branding, visibility-scoped counters, two package rails), `/orgs/{slug}` (public profile + visible packages). Every unreadable outcome is the same 404 an unknown name gets.
- (server) **Download statistics** ([registry/src/stats.rs](server/crates/registry/src/stats.rs), [jobs/src/downloads.rs](server/crates/jobs/src/downloads.rs)). Counting a served archive costs **no I/O** — one mutex-guarded map increment — and the rollup job drains the buffer into `download_stats` with an additive upsert, then writes the totals back onto the search index so `sort:downloads` reads one indexed column. **`HEAD` never counts**: the pub client HEADs before every GET and axum routes HEAD to the GET handler, so without the explicit check every number would be roughly double.
- (server) **Two jobs**: [`reindex`](server/crates/jobs/src/reindex.rs) (chunked, resumable, idempotent full rebuild — off by default, since the index is maintained incrementally and this is the repair path) and [`downloads`](server/crates/jobs/src/downloads.rs) (**on** by default: it is the only thing that moves buffered counts into the database).
- (server) **Index maintenance on every lifecycle change.** Publish, retract/restore, hard delete, and the new `RegistryService::set_options` rebuild the package's document through one projection (`pub_registry::index`), which is also what the reindex job runs — so a repaired index is byte-for-byte what incremental maintenance would have produced.
- (server) **83 tests** (620 → 703 workspace-wide). Contract functions `package_search`, `search_visibility`, and `download_stats` run on **both** backends (the Postgres leg against a throwaway `postgres:17-alpine`), covering relevance ordering, the whole filter vocabulary with negation, injection attempts as data, keyset pagination, ordering-bound cursors, additive rollups, and a 3-visibility × 4-principal matrix asserted on listings, text queries, `is:` probes, by-name lookups, facet totals, and counters. [`read_model.rs`](server/crates/api/tests/read_model.rs) drives the HTTP surface over packages published through the real three-step flow; [`reindex.rs`](server/crates/jobs/tests/reindex.rs) proves a sweep resumes across a restart and drops packages with nothing live.

Descending is its own method rather than a flag: reversing a page in the API layer would give newest-first *within* a page while paging from the oldest.
- (server) **Query-string failures answer in the app-API envelope.** Axum's `Query` rejection is plain text, which made `?limit=x` the one `/api/…` client error that did not answer `{"status":"error",…}`; the new `QueryParams` extractor maps it onto `invalid_argument` with a length-capped detail.
- (server) `Repositories` carries `search` and `stats`; `latest_index` moved into `pub_registry` so the pub protocol listing, the proxy's re-emission, and the search index cannot disagree about which version is "latest"; `[branding]`, `[jobs.reindex]`, and `[jobs.downloads]` join the boot config (branding moves to the `settings` table with the runtime-settings cache, like `require_auth_for_read`).
- (docs) [Decision 11](docs/decisions.md#11--search-behind-a-trait) gains an implementation addendum (index as derived data, the visibility rule, the never-failing parser, the ascending-score convention, cursor binding, backend recall differences, and the local-only scope of the read model); [S-04.d](docs/security.md#1-authentication) records the read model's enumeration surfaces and the two deliberate non-secrets; architecture.md documents the new tables, jobs, and the read-model plane.

### Notes

- **Proxied packages are installable but not browsable.** A name that resolves through the upstream proxy has no package row here, so the app API answers 404 for it. Rendering somebody else's metadata under our chrome is a product decision of its own and lands with the upstream-cache admin surface.
- **The publishing account is shown only inside the owning org.** Organizations are this registry's publishers; the individual who ran `dart pub publish` is not part of that public contract.

## 2026-08-07 — proxy adversarial review, arbitrated by the real client against the real pub.dev

An attack pass over the upstream proxy surface, with the **real `dart pub` client** (Dart SDK 3.12.2) driving a live `pubd` (SQLite + filesystem blobs + in-memory KV) whose upstream is the **real pub.dev** — every upstream connection routed through a local counting proxy, so "was upstream asked?" is an exact number rather than an impression. Four defects fixed, three structural residues recorded in [docs/security.md](docs/security.md) (S-04.c, S-16.b, and S-19.a's new rules).

**The arbiter run.** `dart pub get` resolved an 11-package graph (`http` and its transitive closure) through `/o/acme/pub`, wrote **our** URL and **pub.dev's own** `archive_sha256` into `pubspec.lock` for all 11 (checked against pub.dev's live listings), and the resolved code ran; the proxied `collection-1.19.1.tar.gz` is byte-identical to pub.dev's. A second resolve with `PUB_CACHE` wiped opened **zero** upstream connections against eleven for the cold one. With pub.dev made genuinely unreachable and the listing TTL forced to 0, the same graph still resolved from cache while an uncached name answered one clean `could not find package args` — no retry storm. Then the **dependency-confusion demonstration**: `path` (a real pub.dev package, at that point cached here with all 76 of its upstream versions) published locally as `9.9.9`; a fresh consumer resolved `path 9.9.9`, locked our hash, ran code only the local package defines, and never touched upstream — while the same name stays a `404` for anyone who cannot read it, rather than falling through to pub.dev's namesake. Full transcript in [docs/protocol.md](docs/protocol.md#conformance-testing).

### Fixed

- (server) **The SSRF guard blocked private *addresses* but not the *names* for them** ([registry/src/upstream/http.rs](server/crates/registry/src/upstream/http.rs)). The check runs before DNS, so `169.254.169.254` was refused while `metadata.google.internal` — one upstream-supplied `archive_url` or redirect away — was not. Names reserved for loopback and private use are now refused for hosts **upstream** picks: `localhost`/`*.localhost` (RFC 6761), `*.local` (RFC 6762), `*.internal` (ICANN's private-use TLD, home of GCP's metadata server) and `metadata.goog`, `home.arpa` (RFC 8375). The *configured* host stays exempt, so `https://packages.corp.internal` remains a supported mirror. Numeric-notation dodges (`https://2130706433/`, `0x7f000001`, `127.1`) were already covered by WHATWG host parsing — now pinned by a test, since it is a dependency's property rather than ours.
- (server) **One bad package could close the proxy for every package** ([registry/src/upstream.rs](server/crates/registry/src/upstream.rs)). The instance-wide circuit breaker counted every non-404 failure, so a listing our own validator refuses — or one past `max_listing_bytes` — was indistinguishable from an outage. The pub client re-fetches a listing before *every* resolve, so a single CI job on a single such package would have opened the circuit repeatedly, degrading everything else to stale-or-404. Only **reachability** failures now count; an unusable document is recorded as `upstream_fetch_total{outcome="unusable"}` and nothing more. Symmetrically the **archive** path now feeds the breaker on transport failures: with a warm listing cache and a dead archive host it was the only branch still going out, and the one the breaker could not see, so every download paid its full retry budget and timeout with no circuit ever opening.
- (server) **A truncated download was reported as tampering.** Hash-before-store already made short bytes harmless — they hash to something else and are never stored — but the conclusion arrived through the hash check, which filed a dropped connection in the S-19 quarantine register as upstream substitution and emitted a `security`-category alarm for a network hiccup. A body that stops short of its own `Content-Length` is now named as the transport failure it is; the version stays ingestible, so the next honest answer caches normally.
- (server) **Upstream's `Content-Length` could size an allocation.** The archive buffer was pre-reserved from the advertised length, so an upstream announcing `max_archive_bytes` and then sending nothing cost 100 MB of resident memory per in-flight fetch (× `max_concurrent_fetches`) for as long as the archive timeout allowed. The hint is clamped to 1 MiB and `Vec` growth pays for real archives.

### Added

- (server) **10 tests** for the above: SSRF refusal of special-use hostnames and of every numeric loopback notation; an unusable listing and an oversized one leaving the circuit closed for other packages; a dead archive host opening the circuit behind a warm listing cache; a successful download clearing the failure count; a truncated body storing nothing, quarantining nothing, and staying ingestible; the buffer clamp; plus two proxy conformance tests — a **proxied** response gzips its listing and answers `HEAD` exactly as it answers `GET` (the client HEADs before it downloads, and the proxied path builds its body somewhere else than the local one), and a hostile upstream document changes what our fields *say* and never what fields *exist*: extra top-level and per-version keys are dropped, a wrong-typed `isDiscontinued`/`retracted` collapses to our default rather than travelling through, a non-string `replacedBy` is dropped, and `latest` is recomputed so upstream cannot name a version we do not serve.

### Changed

- (docs) [S-04.c](docs/security.md#1-authentication) records the residue this review could **not** close, with measurements: an unclaimed-name miss costs an upstream round trip and a claimed-but-unreadable name costs two indexed reads, so two byte-identical 404s differ by 0.34 ms vs 219 ms and an anonymous prober can decide whether a name is claimed on the instance by timing alone. Every uniform-latency alternative is worse than the leak; `registry.require_auth_for_read = true` is what closes it, and that is now the documented reason the flag exists. [S-16.b](docs/security.md#4-supply-chain--registry-integrity) records that `upstream_policy = block` binds to the org's **base**, not its members — the same token resolves upstream packages through the public root — and [S-19.a](docs/security.md#4-supply-chain--registry-integrity) gains the four rules above. Decision 07 carries the breaker rule; architecture.md and protocol.md carry the verification.

## 2026-08-07 — mirror mode and supply-chain guards

The second half of [decision 07](docs/decisions.md#07--upstream-proxy-read-through-cache-and-mirror-mode): a leader-locked worker that warms the read-through pipeline instead of duplicating it, the [S-17](docs/security.md#4-supply-chain--registry-integrity) shadowing alarm the mirror makes detectable, and the unreferenced-blob GC that finally closes [S-20.a](docs/security.md#4-supply-chain--registry-integrity)'s staged-upload gap. Everything new is **off by default**. Design refinements recorded in [docs/decisions.md](docs/decisions.md) (decision 06 and 07 addenda) and as amendment S-17.a in [docs/security.md](docs/security.md).

**Verified against the real pub.dev**: a `full` sweep over its 86 642-name index mirrored metadata and archives, was killed mid-sweep, and resumed at the stored offset with zero upstream requests for the packages the interrupted tick had already saved; a locally claimed name pub.dev also carries raised exactly one S-17 alarm and was never mirrored; a GC dry run enumerated the resulting 58 objects and found every one referenced.

### Added

- (server) **Mirror sync worker** ([jobs/src/mirror.rs](server/crates/jobs/src/mirror.rs)) in three modes from `[upstream.mirror] mode`: `off` (default), `recent` (re-poll the packages this instance already caches, oldest snapshot first), `full` (enumerate upstream's `/api/package-names` once, then behave like `recent` until `resweep_after` starts the next enumeration). It drives `UpstreamService::refresh` — the read-through pipeline with the read TTL replaced by a caller-supplied freshness floor — so there is **no second ingest path**: same pubspec validator (S-20), same hash-before-store rule (S-19), same byte-drift freeze, same circuit breaker, semaphore, and single-flight guard. Chunked (`chunk` bounds one tick's hold on the leader lock, `concurrency` bounds our in-flight refreshes while the service's semaphore still bounds upstream's), and an open circuit skips the whole tick rather than spending the half-open probe on the first name of a chunk.
- (server) **A sweep that survives restarts.** `jobs.cursor` holds `{page, offset, completed_at}`, so a pod rescheduled 30 000 names into the index resumes there instead of at zero; `refresh` answers `Fresh` without asking upstream for anything inside the floor, which makes re-walking already-covered names one indexed read each. The fetched index page is cached in-process purely to avoid re-downloading megabytes per tick — losing it costs one fetch, never progress. **Enumeration repeats** (`resweep_after`, default 24 h): it is decision 07's drift repair *and* the only channel through which this instance can learn that upstream has started carrying a name we claim, since the read path structurally never asks upstream about a claimed name (S-16).
- (server) **S-17 shadowing alarms** ([registry/src/shadow.rs](server/crates/registry/src/shadow.rs)): one implementation, two callers, because the condition has two arrival orders — a publish claiming a name the proxy already caches (detected in the publish pipeline, on the first publish of that name) and upstream starting to carry a name we already claim (detected only on the mirror sweep). The local package keeps winning, before and after; the alarm is a notification register (`shadowing_alarms`, one row per name, `org_id` = the claim holder = the audience) with a `upstream.shadowing` audit event and a `PackageShadowed` domain event in the `security` notification category. Raised **once per incident** and counted thereafter — an hourly sweep must not re-page the same admins — and a sighting after an acknowledgement is a new incident. A shadowed name is observed and then skipped: mirroring it would store bytes resolution can never serve.
- (server) **Unreferenced-blob GC** ([jobs/src/gc.rs](server/crates/jobs/src/gc.rs)), disabled and dry-run by default. A content-addressed key is collectable only when **both** registers agree nothing live points at it — live `versions` *and* cached `upstream_versions`, because the proxy stores archives under the same keys a local publish does — and only outside a grace period (`min_age`, default 24 h, validated to exceed the 1-hour staged-upload TTL), since publish writes bytes before the version row and a staged upload is finalizable with nothing referencing it. Keys the job does not fully recognize are left strictly alone; a backend that cannot enumerate fails the job instead of deleting on incomplete information. Abandoned staged uploads are swept by age, closing the second half of S-20.a.
- (server) **`JobRepo` and migration 0006** in both dialects: `jobs` (opaque cursor, phase, run/success timestamps, last error, additive counters), `upstream_quarantine` (S-19 refusals, one row per `(name, version)` with an occurrence counter), `shadowing_alarms` (S-17, with acknowledgement). Counters are added to rather than written, so a run that dies between checkpoints leaves its partial progress recorded — and `begin_run` handing back the stored cursor is what makes a leader change resume rather than restart.
- (server) **Admin read model** (repo + service functions, no HTTP routes yet): `UpstreamService::cached_packages` (per-package version counts and the bytes we actually hold, keyset-paginated), `quarantined`, `shadowing_alarms`, `acknowledge_shadowing`, plus `MirrorWorker::status` / `BlobGc::status` for job state. `UpstreamRepo` gained `list_stale`, `list_cached`, `count_cached_with_sha256`, and the two registers' writers; `BlobStore` gained `list` (with sizes and ages — the age is what makes GC safe).
- (server) **Metrics** (decision 23; the counters are always maintained, the exporter stays config-gated and off): `upstream_fetch_total{kind,outcome}` replacing the two per-endpoint counters, `cache_hit_ratio`, `upstream_sync_lag_seconds`, `quarantine_total`, `shadowing_alarms_total`, `blob_gc_{scanned,deleted,bytes}_total`.
- (server) **`[upstream.mirror]` and `[jobs.blob_gc]` config**: mode, interval, chunk, concurrency, `refresh_after_secs`, `resweep_after_secs`, `archives` + `archive_versions`; GC `enabled`, `interval_secs`, `dry_run`, `min_age_secs`. Validated at startup — a mirror with `upstream.enabled = false` is refused (a worker fetching packages resolution can never serve looks like a working mirror from outside), as is a GC grace period below the staged-upload TTL — and shown in the effective-config summary. `pubd` registers only the enabled jobs, so a disabled job cannot tick at all.
- (server) **43 tests**: 16 job integration tests over a real database and blob store with only the network scripted — two replicas under one lock never running a tick concurrently (proved by the peak number of simultaneous upstream fetches, not by inspection), `recent` picking up a new upstream version and leaving fresh snapshots alone, archive warm-up, a chunked `full` sweep resuming across a simulated restart and re-enumerating after its window, an S-17 alarm raised once and never mirrored, an open circuit skipping the tick, GC keeping bytes shared with a live version *and* with a cached upstream version, dry-run, grace period, unrecognized keys, abandoned staged uploads, and a blind backend failing the job; 2 proxy conformance tests for the publish-side shadowing order; 3 repository contract functions running against **both** backends (`upstream_mirror_reads`, `supply_chain_registers`, `job_repo`); plus refresh/quarantine-register/cache-inventory/hit-ratio/breaker-peek unit tests and config tests.

### Fixed

- (server) **`/api/package-names` needs `Accept-Encoding: gzip`.** pub.dev answers `406 NotAcceptable` on that endpoint without it ("Client must accept gzip content"), so a full sweep against the real upstream would have failed permanently — found by running the worker against the live service. The header now rides both JSON endpoints and gzip is decoded **by hand** (flate2, with the size cap applied to the *decoded* document, so a few compressed kilobytes cannot decide how much memory the process allocates). The HTTP client is deliberately left without transparent content decoding: a client that silently decodes response bodies would also decode an archive body, and "the bytes we hash and store are the bytes that arrived" is the proxy's core promise ([sharp edge 3](docs/protocol.md#sharp-edges-violate--break-clients), S-19).

### Changed

- (server) `Repositories` gained a `jobs` handle and `BlobStore` a provided `list` (default: `Unimplemented`, because a store that cannot enumerate is not broken — it just cannot be swept). `DomainEvent` gained `PackageShadowed` and `notification_category()`, so the notification center routes by the event's own contract rather than by a lookup table. The Postgres cache-inventory aggregate casts `SUM()` to `bigint` — it answers `NUMERIC` otherwise, which would have made the two backends disagree on the row type.
- (docs) Decision 07 gained the mirror addendum (six decisions the "periodic sync worker" sentence left open), decision 06 the GC addendum, S-19 the quarantine register, S-20.a the closed staged-upload gap, and protocol.md the distinction between consuming upstream's `/api/package-names` and serving one of our own.

## 2026-08-07 — pub.dev read-through proxy

The first half of [decision 07](docs/decisions.md#07--upstream-proxy-read-through-cache-and-mirror-mode): unclaimed package names resolve through pub.dev, cached forever, verified before they are stored. No mirror worker yet — but the ingest pipeline the worker will warm is the one that ships here. Design refinements recorded in [docs/decisions.md](docs/decisions.md) (decision 01 and 07 addenda) and as amendments S-16.a and S-19.a in [docs/security.md](docs/security.md).

### Added

- (server) **Upstream ingest pipeline** ([registry/src/upstream.rs](server/crates/registry/src/upstream.rs)) shared by the read-through path and the future mirror worker: fetch listing → validate every version's pubspec with the **publish** validator (S-20) → snapshot upstream state verbatim (`retracted`, `isDiscontinued`, `replacedBy`, `advisoriesUpdated`, full pubspec JSON, `archive_sha256`) → on an archive miss, fetch, **verify the advertised sha256 before anything is stored** (S-19), then store byte-identical and content-addressed under the same `<format>/<shard>/<sha>.tar.gz` key a local publish uses. Archives are never re-tarred or re-gzipped: the hash in a user's `pubspec.lock` is the hash of upstream's exact bytes.
- (server) **Integrity refusals that are events, not log lines** (S-19): a hash mismatch is a **quarantine** — never stored, never served, audited as `upstream.quarantine` with both hashes and emitted as a domain event, answered to the client as a permanent 404. Upstream advertising a *different* hash for a version we already hold is **byte-drift**: the cached bytes keep being served, the change is audited as `upstream.drift` and alarmed, and nothing is overwritten. The freeze is enforced twice on purpose — the service computes the preserved value and both repositories' upsert independently keeps it (`CASE WHEN cached THEN … END`), so a future caller cannot reintroduce the overwrite.
- (server) **`UpstreamClient` behind a trait** with a real implementation over reqwest + rustls ([registry/src/upstream/http.rs](server/crates/registry/src/upstream/http.rs)): timeouts, exponential-backoff retries on transient failures only, an optional bearer credential for authenticated mirrors, bodies bounded *while* they arrive, and an SSRF guard on every URL upstream chooses — https only, no user-info, no loopback/private/link-local/CGNAT destination (`169.254.169.254` included), redirects capped and re-checked, and a configured token never following a cross-host hop. Every proxy behaviour worth asserting is defined by upstream *misbehaving*, so no test in the workspace opens a socket.
- (server) **Degradation that never becomes a retry storm**: an unreachable upstream or an open circuit serves the cached listing/archive with a staleness marker in tracing and metrics, and anything never cached answers **404**, never 5xx — the client retries 5xx up to seven times ([sharp edge 2](docs/protocol.md#sharp-edges-violate--break-clients)). A per-instance circuit breaker (half-open admits one probe with its budget already spent), a per-upstream concurrency semaphore, and a single-flight guard so N simultaneous misses of one package cause **one** upstream fetch. An upstream 404 neither evicts a snapshot we hold nor counts against the breaker.
- (server) **Resolution wiring** (decision 01, S-16): the proxy is reachable from exactly one expression — the `Resolution::Unclaimed` arm of `resolve_target`, whose `Target::Upstream` variant *carries* the service, so no handler can proxy a claimed name even by accident. Proxied listings re-emit upstream's flags, hashes, and pubspecs verbatim with `archive_url` rewritten under the requesting base ([sharp edge 3](docs/protocol.md#sharp-edges-violate--break-clients)); local and upstream versions of one name are never merged. `advisoriesUpdated` is stored but not advertised while `…/advisories` is unimplemented (sharp edge 11).
- (server) **Per-org upstream policy** (`orgs.upstream_policy`, `allow` | `block`, migration **0005** in both dialects): a blocked org answers the *same* 404 for an unclaimed name that an unknown name gets — a distinct status would confirm the package exists upstream (S-04). `delay`/`allowlist` are later variants of the same enum; `OrgRepo::set_upstream_policy` is their write path.
- (server) **`UpstreamRepo`** in `core` with implementations on both backends: snapshot upsert that **never deletes** a version upstream stopped listing (we may already hold its bytes), precedence-ordered `list_versions`, and `mark_cached` guarded by the content hash so a row whose hash moved under a concurrent snapshot cannot be marked cached for the wrong content.
- (server) **`[upstream]` config section**: `enabled` (default true), `base_url` (default `https://pub.dev`, https required in production — the listing carries the hash we verify against), `user_agent`, optional `auth_token` (a masked `Secret`), connect/listing/archive timeouts, retry count and backoff bounds, `max_archive_bytes`, `max_listing_bytes`, `listing_ttl_secs` (default 300), `max_concurrent_fetches`, and the circuit-breaker thresholds — validated at startup even when disabled, and shown in the effective-config summary with the token masked.
- (server) **67 tests**: a 21-test proxy conformance suite ([api/tests/proxy.rs](server/crates/api/tests/proxy.rs)) over a scripted upstream — cold miss caching and re-emitting under our own base, a warm cache proving upstream was not asked, TTL refresh, sha256-mismatch quarantine (refused, unstored, audited, and still ingestible once upstream is honest again), byte-drift keeping the pinned hash and the original bytes, stale serving and 404-not-5xx under an outage, the circuit breaker, single-flight collapsing eight concurrent misses into one fetch, oversized and hostile-pubspec refusals, the four resolution-order cases, per-org `block`, and verbatim flag re-emission; 23 registry unit/pipeline tests; an `upstream_repo` contract function running against **both** database backends; SSRF-guard, status-mapping, depth-check, and config tests.

### Changed

- (server) `Pubspec::parse` is now YAML decoding plus `Pubspec::from_json`, the shared rules half — so "an upstream pubspec clears the same bar as a local publish" is one implementation rather than two. The depth cap walks iteratively: a JSON document arrives already built, and recursing over an attacker-shaped tree is how a depth check becomes the overflow it was meant to prevent.
- (server) `Repositories` gained an `upstream` handle, `AppState` an `upstream: Option<Arc<UpstreamService>>` (absent = no upstream branch in the resolution path at all, which is what an air-gapped operator buys), `Org` an `upstream_policy` field, and `DomainEvent::org_id()` returns `Option<OrgId>` — proxy integrity alarms are instance-scoped, and silently attributing them to some org would show them to the wrong audience (S-32).
- (server) The archive response omits `Content-Length` rather than claiming zero when a size is unknown; proxied sizes are measured while caching and frozen with the hash.

## 2026-08-07 — registry conformance and security review

An adversarial pass over the registry slice, arbitrated by the **real `dart pub` client** (Dart SDK 3.12.2) driving a live `pubd` on SQLite + filesystem blobs: token add → publish → resolve in a consumer package → retraction visibility, plus the 401/403 credential-handling asymmetry that only exists in the client's source. Findings recorded in [docs/security.md](docs/security.md) (S-04.b, S-20.a, S-24.b/c) and [docs/protocol.md](docs/protocol.md).

### Fixed

- (server) **An archive could hide bytes from the validator** (S-20). A tar reader stops at the end-of-archive marker and a single-member gzip reader stops at the end of member one, so a second concatenated gzip member — which `tar -xzf` decodes — or a payload past the zero blocks passed ingest unseen and was then stored and served forever: the validated archive was a *prefix* of the published one. The stream is now decoded multi-member and drained to EOF, and everything after the marker must be NUL padding (`ArchiveError::TrailingData`). Verified not to reject archives produced by the real client, which pad with zeros.
- (server) **A duplicate-version conflict leaked version existence across orgs** (S-04, decision 01). Publishing into a name another org holds reported "version 1.0.0 already exists" when the version happened to exist — a version-existence oracle for somebody else's private package. Ownership is now decided before existence, and both routes to the denial emit the same sentence.
- (server) **A wrong method under a registry base answered a bodyless 405.** The router produced it before any handler, so the pub client — which parses the body of every failure — got unparseable bytes. It now carries the spec error shape, still as a permanent 4xx.
- (server) **The `Bearer` scheme was matched case-sensitively.** Auth schemes are case-insensitive (RFC 9110 §11.1), and on this plane a rejected credential is a 401 — which makes the client *delete the stored token*. Header casing must not cost a developer their credential.
- (server) **A rejected publish was audited without naming the package** (S-22): the pub protocol pins no name (step 1 carries none), so every failure landed in the log as an anonymous `package.publish` failure. The pipeline now reports the parsed name back, and rejections after the pubspec parses are audited as `name@version`.
- (server) Caller-supplied names and archive filenames are clipped before they are quoted back in a 404 message (the ingest path already did this for tar entry paths).

### Added

- (server) **S-24 publish rate limit** — `registry.rate_limit.publish_per_hour_org` (default 30), previously normative but unimplemented. It is spent by the upload step, which is the step that costs storage and is reachable directly; trips answer `429 + Retry-After` and are audit-logged as `package.publish.throttled`. A KV outage fails **open** here (an already-authorized write), the opposite of the auth-abuse buckets.
- (server) **Adversarial suite** ([api/tests/pub_attack.rs](server/crates/api/tests/pub_attack.rs), 9 tests): the publish authorization matrix (read-scoped token, foreign-org token, Read-role member, non-member — every cell a 403 that keeps the credential, at step 1 *and* at the byte sink), 13 hostile archives each required to answer a permanent 4xx (truncated gzip, gzip-in-gzip, tar garbage, traversal, absolute path, duplicate entries, missing/invalid pubspec, YAML anchor bomb, gzip bomb, 10 001 entries, smuggled second member), byte-identical responses for private-vs-unknown names, blob keys that no crafted name or version can steer, and a finalize session that cannot be redeemed from another org.
- (server) **Conformance re-derivations** in [api/tests/protocol.rs](server/crates/api/tests/protocol.rs): 405 responses speak the spec shape, the bearer scheme is case-insensitive, no valid credential is ever answered with 401 (a seven-case matrix over the read *and* publish paths), listing and error bodies carry exactly the documented field set read from the response bytes, and archives answer `HEAD` with the same metadata as `GET` (the client HEADs before it downloads).

## 2026-08-07 — pub protocol v2 HTTP surface

The registry becomes usable by `dart pub`: the Hosted Pub Repository Spec v2 endpoints on both virtual bases (`/o/{org}/pub` and the public root `/pub`), the CLI-token authentication plane, and the decision 05 status ladder — with a conformance suite that encodes [docs/protocol.md](docs/protocol.md) sharp edge by sharp edge. Design refinements recorded in [docs/decisions.md](docs/decisions.md) (decision 01, 05 and 13 addenda) and as amendment S-14.a in [docs/security.md](docs/security.md).

### Added

- (server) **Pub protocol routes** ([api/src/protocol/](server/crates/api/src/protocol/)), one handler set mounted on both bases (`nest` prefixes the OpenAPI paths too, so neither mount can drift): `GET B/api/packages/{name}` (version listing — `name`, `latest`, `versions[]` with `version`/`retracted`/`archive_url`/`archive_sha256`/`pubspec`, `isDiscontinued`/`replacedBy`, served as `application/vnd.pub.v2+json`); the three-step publish `GET B/api/packages/versions/new` → `POST B/api/packages/versions/newUpload` (multipart field `file`, `204` + `Location`) → `GET B/api/packages/versions/newUploadFinish/{session}` (`200 {"success":…}` / `400 {"error":…}`); `GET B/api/archives/{name}-{version}.tar.gz` honouring `DownloadPlan` (307 to a presigned URL, or the stored bytes streamed); and the legacy `GET B/api/packages/{name}/versions/{version}` and `GET B/packages/{name}/versions/{version}.tar.gz`. - (server) **CLI-token authentication plane for pub routes** (S-13/S-14): the `Principal` extractor takes the token from `Authorization: Bearer` **only** — the spec has no query-parameter credential, and `?token=` would put live secrets into access logs and `pubspec.lock` files. Offline CRC/prefix/charset validation runs before any database lookup, which is also what structurally excludes browser access JWTs from this plane (decision 03). Scopes, the org binding, and the org role are three independent checks; package patterns narrow reads of *private* packages and are enforced at publish finalize, where the package name first exists. `AuthService::authenticate_cli_token`/`token_actor`/`touch_cli_token` carry it, with the S-24 "30 failed token authentications per IP per minute" bucket answering 429 + `Retry-After` instead of a 401 that would delete a bystander's stored token.
- (server) **Status ladder** (decision 05, S-04/S-14) in one place ([protocol/error.rs](server/crates/api/src/protocol/error.rs)): unreadable-or-unknown → **404** with no challenge; missing/invalid credentials → **401**; valid-but-insufficient on a visible resource → **403**; both 401 and 403 carry `WWW-Authenticate: Bearer realm="pub", message="…"` with the message sanitized and capped at 1024 chars — the CLI's only messaging channel, so every denial names the fix (`dart pub token add <base>`, the missing scope, the missing role). Permanent failures are 4xx by construction, `Conflict` included (finalize answers 400, not 409, and a unit test asserts no permanent error can map to 5xx — the client retries those up to 7 times).
- (server) **Base-scoped resolution** (decision 01, S-16): `PackageRepo::resolve_in_base` — a provided method, so the policy exists once above both SQL dialects and runs through the `authorize()` chokepoint. Inside `/o/{org}/pub`: org-owned → instance-public → (upstream iff unclaimed); at `/pub`: public only. "Local always wins" is structural rather than conventional — `Resolution::Unclaimed`, the only value that may ever permit an upstream lookup, is produced on exactly one path, after `lookup_claim` came back empty. Handlers never call `get_by_name` on a read path.
- (server) `registry.require_auth_for_read` (decision 05): flips the protocol to token-only reads, where anonymous requests get the spec-mandated 401 + onboarding message instead of the anti-enumeration 404. `auth.rate_limit.token_auth_fail_per_ip_minute` (S-24, default 30). `BlobStore::get` — the in-process read path, distinct from `download`, which plans a *client* response and may answer with a redirect. `core::token::patterns_allow` shared by the read narrowing and the publish check.
- (server) 82 tests: a 42-test conformance suite ([api/tests/protocol.rs](server/crates/api/tests/protocol.rs)) named after the sharp edges it pins and driving the router exactly as the CLI does — the ladder (404-not-401, 403-with-challenge for scope *and* role, indistinguishable expired/revoked tokens, both credential planes rejecting each other's tokens), listing field types (`archive_sha256` exactly 64 lowercase hex, booleans, full pubspec), the publish flow following the advertised URLs (happy path, duplicate → 400, corrupt archive → 400, junk accepted at upload and refused at finalize, single-use sessions, finalize bound to its credential, pattern-scoped tokens passing step 1 and failing step 3), byte-stability across a restart on two blob backends, subpath bases, `Accept` negotiation and the 406, retraction/hard-delete visibility, resolution order across bases, legacy endpoints, and both mounts being present in the OpenAPI document; plus 39 unit tests and a `resolve_in_base` contract function running on **both** database backends.

## 2026-08-06 — auth slice: adversarial security review

Findings from an attack-oriented review of the just-landed auth slice. Every fix ships with the attack that motivated it ([api/tests/attack.rs](server/crates/api/tests/attack.rs), 20 tests); the normative consequences are recorded as amendments S-03.a, S-04.a, S-12.a, S-24.a/b and S-25.a in [docs/security.md](docs/security.md).

### Security

- (server) **OTP attempt budget was not atomic.** The ≤5-wrong-attempts counter lived inside the pending-auth record and was read-modify-written per verification, so guesses fired in parallel shared a single increment and the budget bounded nothing. The counter moved to its own KV key behind a new atomic `Kv::incr` primitive (Redis `INCR`+`PEXPIRE`, moka per-key upsert), and the attempt is now spent **before** the code is compared (S-03/S-03.a).
- (server) **`X-Forwarded-For` was trusted unconditionally, leftmost hop first.** Every S-24 per-IP limit could be bypassed by rotating the header, and any address's bucket and audit trail could be poisoned by claiming to be it — including behind a correctly configured reverse proxy, where the leftmost entry is exactly the client-supplied one. New `server.trust_proxy_headers` (default **false**) ignores forwarding headers in favour of the socket peer; when enabled it reads the **rightmost** entry. `pubd` now serves with connect-info so a peer address exists (S-24.a/b).
- (server) **Credential redemption had no rate limit.** `POST /api/v1/auth/otp/verify` and `/auth/refresh` were unthrottled, so the per-code ≤5 budget was sidestepped by simply requesting fresh codes. Both now carry S-24's "login 10/min/IP" bucket (`auth.rate_limit.login_per_ip_minute`).
- (server) **Secrets were reachable through derived `Debug`.** The OTP pepper, JWT signing seeds, SMTP password, S3 keys, connection-URL passwords, minted token secrets and the access/refresh pair were all printable via a stray `{:?}`, `#[instrument]` field or panic message — S-25 masking covered only the startup summary. Configured secrets now use a `Secret` newtype (redacting `Debug`, no `Display`, explicit `.expose()`); `DatabaseConfig`/`KvConfig` mask their URLs; `AuthPolicy`, `LoginSuccess`, `MintedToken` and `SmtpSettings` hand-write redacting `Debug` (S-25.a).
- (server) **S-31 was enforced at registration but not at sign-in.** An account whose domain had since left the allowlist could still redeem a valid code; `verify_otp` now applies the domain gate to existing accounts too, with the same uniform `invalid_code` rejection (S-04).
- (server) **S-12's server-side `Origin`/`Sec-Fetch-Site` verification was missing** — only the custom header was checked, leaving CSRF defence entirely to the browser. `/api/` mutations now compare the parsed `Origin` triple against `server.public_url` and reject non-same-site `Sec-Fetch-Site`, while header-less CLI/CI clients keep working (S-12.a).
- (server) **Anti-enumeration timing.** `request_otp` no longer skips the account lookup and template render for policy-rejected addresses; all branches perform identical server-side work. The remaining SMTP-hand-off asymmetry is documented as an accepted, bounded risk with its planned mitigation (S-04.a).

### Added

- (server) `Kv::incr` — atomic counter with TTL on the KV seam, contracted as atomic because authentication budgets are decided by its return value.
- (server) `_FILE`-suffixed environment variables (S-25): secrets read from mounted files with trailing newlines trimmed; unreadable paths and the ambiguous "both `X` and `X_FILE` set" case are startup errors.
- (server) `RequestMeta` typed extractor replacing ad-hoc `HeaderMap` plumbing, so handlers cannot reach for a raw forwarding header instead of the resolved client identity.
- (server) 39 tests: the 20-test adversarial suite (JWT algorithm confusion with the Ed25519 public key as HMAC secret, `alg:none`, unknown `kid`; parallel OTP guessing; resend-rewind of the attempt budget; KV-outage fail-closed on both the access-token and OTP paths; concurrent refresh races; refresh-plaintext persistence; bundled `admin` scope escalation; forwarded-header spoofing and poisoning; cross-site mutations; post-policy domain sign-in) plus KV atomicity, config secret-redaction, `_FILE` handling, and JWT claim-set assertions.
